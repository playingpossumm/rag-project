Retrieval Inspector · design decision

Four ambient fields, side by side

The brief left the ambient visual undecided and asked to see the options together. Each one below is generative, seeded and deterministic, and takes its structure from something true about the pipeline rather than being decoration with a lab coat on. Each is shown twice: as a masthead band that is always present, and as a backdrop for the idle state that gives way once results arrive. Back to the inspector.

OPTION A

Basin

Marks drift on a noise field and are drawn toward twenty basins — one per document in the corpus. Read: an embedding space settling into the documents it is made of. The marks are marks; they do not stand for individual chunks.

What it argues
Retrieval is geometry. The corpus has shape, and a query lands somewhere in it.
Where it is weak
Closest of the four to a stock particle flow field. Its specificity is in the basin count, which nobody reads off the screen. Motion never stops, so it competes with the charts.
OPTION B

Lattice

Five stage columns and eight rank rows — the bump chart with the data taken out. Marks advance a stage at a time and change rank as they go. The quietest of the four, and the only one that reads as the same instrument as the page it sits on.

What it argues
Rank is the unit of this system. It rehearses how to read the bump chart before you meet one.
Where it is weak
It rhymes with the real chart closely enough to be mistaken for one. A visual that looks like data but is not is the one failure mode this page cannot afford.
OPTION C

Fringe

Two wave sources, one per retriever, and the interference between them. Where the crests coincide the field brightens — which is what reciprocal rank fusion rewards: the passages both retrievers found. The only field of the four that depicts the idea the pipeline is built on.

What it argues
Two retrievers, and the answer is where they agree. It is the thesis of the pipeline rendered as a physical process.
Where it is weak
It carries the most colour of the four, and it uses the same two hues the charts use for documents — a viewer could read meaning into the hue that is not there.
OPTION D

Settle

Marks fall and stack into ranked rows, then stop. The only field with an end state, which is its argument: it performs the sort once on load and then gets out of the way, rather than moving forever behind text.

What it argues
Ranking is the job, and it finishes. Motion that ends respects the reading that follows it.
Where it is weak
After the first two seconds it is a static rule pattern, so it stops paying for itself on a page you keep open. Re-running it on every query would be motion pretending to be progress.

The recommendation, if you want one

Option B (Lattice) for the masthead, Option C (Fringe) for the idle backdrop. They do different jobs, and using both is not a compromise between them.

The masthead is permanent and sits above real charts all day, so it has to be the thing that never competes — that is B, which is nearly all hairline and moves at a pace you notice only if you look for it. Its weakness (looking like the real chart) is answerable by keeping it small and unlabelled, which a masthead band already is.

The idle state is the opposite case: it exists precisely because there is nothing to read yet, and it is gone the moment there is. That is where C earns its colour — it is the one field that teaches something before you have asked anything, and it never shares the screen with the charts it could be confused with.

Against the brief, A is the one to drop. It is the closest to a default particle field, and its only claim to specificity is a basin count no viewer can see. D is a real idea, but a load animation more than an ambient one.
