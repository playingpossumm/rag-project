How this works.

A retrieval system built by hand, with every stage on screen.

Retrieval-augmented generation answers a question by searching a set of documents and quoting what it finds. A framework will build one in an afternoon. It works, and it hides every decision inside it.

This system is built from parts instead. Each stage is drawn as it runs, each setting can be changed and the question re-run, and each default was chosen by measuring the alternatives. This page explains what the stages are.

Compared with a closed product Five questions about the middle

NotebookLM, Glean and the enterprise search tools sold to companies will answer better than this. They have larger models and far more compute. They also answer from a closed middle. You put a question in and an answer comes out. What happened in between is not shown. Here are five questions about that middle, and what each version can say.

Five changes that sounded obviously right were measured and dropped. Three of them:

  • Adding each document's title to every passage cost source recall. It was built, measured and reverted.
  • A reranker eight times larger fixed the same two questions the small one fixed. It took ten times as long.
  • Compressing the cross-encoder ran 1.5× faster and barely moved the rankings. It also made the system refuse questions it could answer.

The engineering log has all five, with their numbers.

A guide What happens when you ask

This site is a learning project. It was built to understand retrieval by making every part of it visible, rather than to serve documents at scale. What you can search here is three prepared sets: 36 machine-learning papers, 45 ornithology articles, and 35 quantitative-finance papers. They are fixed. Each one had to be indexed, given a set of labelled questions, and calibrated before any number on this site could be measured.

To point it at your own documents, or to have it run the search live rather than replay a recorded one, run the project from GitHub. The repository also lists every document in all three sets.

Pick a document set, type a question, and the answer comes back with the passage it rests on and the route it took. Nothing is generated by default: what you read is the retrieved text, verbatim. Here is the whole path, in order.

The answers cite their sources by filename. Every document in every set is listed with its title and format, and the whole system is open source. Every stage drawn on these pages is a function you can read.

  1. The documents are cut into passages

    Each document is split into overlapping windows of about 210 tokens. A whole document is too large to compare against a single question. The windows overlap so that an answer sitting across a cut still appears whole in one of them.

  2. Two retrievers search, at the same moment

    Dense retrieval compares meaning, by turning the question and every passage into vectors. BM25 compares exact words, weighting rare ones heavily. Each one fails where the other works. Dense retrieval handles a question worded differently from its answer, and misses exact tokens such as a model number. BM25 finds those tokens immediately, and returns nothing when the question and the answer share no words. Running both covers each gap.

  3. The two rankings are fused

    Each retriever contributes 1/(60 + rank) to every passage it returned, and the sums are sorted. Only the position counts, never the score itself. The two retrievers measure different things on different scales, so adding their numbers together would require inventing a conversion between them.

  4. A cross-encoder re-reads the survivors

    The shortlist is scored again by a model that reads the question and the passage together and answers "does this passage answer this question". The earlier stages turned the question and the passage into numbers separately, then compared the numbers. This model reads the two together. It is more accurate and much slower, which is why it only sees a shortlist.

  5. At most two passages per document survive

    The diversity cap. This is a trade. It lowers the hit rate a little and raises how many of the answering documents come back. A question answered by four papers should not return four passages from one of them.

  6. The gate decides whether to answer at all

    If the best passage scores below this corpus's threshold, the system declines instead of answering. A search always returns its closest matches, however far away they are. Ask the ornithology set about tax law and it returns five passages about birds. The threshold is set for each set of documents by measuring where its real answers stop and its near-misses begin.

Reading what comes back

The passage is shown verbatim, with only the answering words in bold. The citation names the real document title and the location: a page for a PDF, a slide for a deck, a sheet for a spreadsheet.

The score comes from the cross-encoder and runs roughly −11 to +11. It is neither a probability nor a percentage. A positive score means the passage answers the question. A strongly negative one means the documents probably do not hold the answer.

“Also found” lists passages from other documents that matched. The top passage is sometimes the wrong one. Asked for a bird's fused collarbone, the cross-encoder ranks the pygostyle passage first and the furcula second.

“The corpus does not contain this” means the gate declined. That is the system working. Some of the example questions on the front page are chosen to trigger it.

Glossary Every term this interface uses
RAG
Retrieval-augmented generation. Answering a question by searching a set of documents first and quoting what is found, rather than relying on what a model memorised. retrieval-augmented generation
Corpus
One set of documents, with everything derived from it: its index, its labelled questions, its threshold. Nothing about one corpus transfers to another. It is the finding this project has reused most. document set
Chunk
One passage: a window of about 210 tokens cut from a document, with 40 tokens of overlap onto its neighbour. passage
Locator
Where a passage came from, in the unit its format actually has: a page for a PDF, a slide for a deck, a sheet or section elsewhere. Saying “page 3” of a slide deck sends a reader somewhere that does not exist.
Embedding
A passage or question turned into a list of numbers, positioned so that things meaning similar things sit near each other. vector
Dense retrieval
Search by comparing embeddings. It matches meaning and handles a question worded differently from its answer. It misses rare tokens that carry their meaning by being exact, such as a model number. vector search · semantic search
BM25
Search by exact term overlap, weighting rare words far above common ones. The exact inverse profile: strong on identifiers, blind to paraphrase. sparse retrieval · lexical search
Fusion
Combining two rankings into one. This system uses reciprocal rank fusion: each retriever contributes 1/(60 + rank), so only position counts and no score conversion is needed. RRF · hybrid search
Candidate pool
The shortlist the first stage hands to the reranker. Its size is a latency dial: reranking is over 90% of the time a query takes and costs scale linearly with it. candidate_k
Cross-encoder
A model that reads a question and a passage together and scores whether one answers the other. Far more accurate than comparing two separately-made embeddings, and far too slow to run over a whole corpus. reranker
Reranking
Re-ordering the shortlist with the cross-encoder. On some corpora a fraction of the first stage's ordering is deliberately kept. When a question describes a term instead of naming it, the cross-encoder has little to work with.
Diversity cap
A limit of two passages per document in the final answer. Trades a little hit rate for covering more of the documents that answer the question.
Context expansion
Attaching the neighbouring passages to each result, so a sentence cut by a chunk boundary is still readable. It cannot change any ranking, because it runs after selection.
Abstention threshold
The score below which the system declines to answer. Calibrated per corpus: the same number that costs one corpus a single question costs another ten. the gate · confidence threshold
Golden set
The labelled questions a corpus is scored against, each with the documents and locations that answer it. Every number on the analytics page comes from these.
Adversarial case
A question deliberately included because the documents cannot answer it. Refusing one is a success; answering it is the failure being measured. unanswerable case
any-hit@5
The fraction of questions where at least one correct passage appears in the five returned. Asks "did it find it at all".
MRR
Mean reciprocal rank. Rewards putting the right passage first It scores 1.0 if it is first, 0.5 if second, and so on. mean reciprocal rank
NDCG
A ranking-quality score over all the relevant passages returned, not just the first, discounting each by how far down it sits. normalised discounted cumulative gain
Source recall
How many of the documents that answer a question were returned. The metric hit rate cannot express: returning one of four answering papers scores a perfect hit rate while missing three quarters of the answer.

Built by hand in Python: no retrieval framework, no CDN, no external request from this page. The server binds to localhost, since the documents may be private. A page about private documents should not call a font host, so the fonts are bundled.
